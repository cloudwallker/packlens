# Support and boundaries / 支持与边界

PackLens analyzes a built, standalone package snapshot under `npm-single-package-v1`. It reads the root manifest and local npm/git ignore text; ordinary files contribute names, types and `lstat` sizes. Lifecycle scripts, builds, installs, project/global npm configuration and network activity are outside analysis. Private shadow directories contain empty ordinary-file placeholders and necessary rule metadata and are cleaned after use.

Supported inputs include positive files paths/globs, covered negation/brace behavior, nested ignore files, physical-line edits, tested main/bin/browser string declarations, and forced npm metadata. Bundled dependencies, workspaces, links/junctions, special files, case collisions, unsupported syntax/normalization and changed sources retain uncovered/stale states. Unknown assertions remain unknown. An implicit ancestor workspace is not inspected; the result is specifically standalone.

Limits: 50,000 nodes, depth 64, 1 MiB per control/rule file, and 8 MiB total metadata. Every manifest or virtual `files` list has a fixed cumulative expansion budget of 50,000 branches and 1,048,576 UTF-8 bytes. A string-only preflight proves conservative bounds for balanced alternatives and exact numeric/alphabetic ranges, including intermediate expansions, before the pinned producer runs. Unproven forms (escaped/dollar-prefixed braces, leading `{}`, literal or malformed brace groups, excessive nesting and unsafe-integer ranges) return `LIMIT_EXCEEDED`. This keeps accepted expansions below the producer's silent 4,000,000-character limit. Clients can lower existing node limits but cannot raise these fixed caps. Raw absolute/parent paths are rejected before npm normalization; trailing slashes follow the fixed producer's normalization. Directory globs and covered safe braces retain official matching.

Each interactive user operation gets a fresh 30-second deadline. A single CLI request shares its deadline across capture, baseline and patch, including `--html`; an incomplete simulation exports its incomplete result. HTTP JSON bodies are at most 1 MiB. The server serializes scene changes, requires their expected revision, and retains the latest valid scene after failure. The saved HTML contains baseline plus the latest 20 successful live changes. A full tree is searchable and paginated in groups of 100 displayed entries.

Raw bytes measure the sum of shipped paths, not compressed tarball or download size. Exact integer budgets include virtual manifest/ignore byte changes. Reports use relative paths and a selected public projection; they may contain local filenames and relevant rules. The export checkbox/API `omitRuleText` removes rule bodies and evidence patterns. Share synthetic examples when demonstrating the product.

The live server binds only `127.0.0.1`; open its exact printed address, not `localhost`. The initial exact-Host page bootstraps a temporary session credential in memory; exports and console URLs omit it. APIs do not offer arbitrary file reads, root switching or command execution. `--open` is implemented for Windows default-browser launching; other platforms use the displayed URL.

Validation status: Windows + Node 24.15.0 and the pinned Chromium browser were exercised locally, including a real FileShare.None cleanup failure, unlock and ownership-checked retry. GitHub Actions contains Windows/Linux jobs with the same profile; Linux, macOS and hosted execution remain unverified. Interviews with package authors have not run.

Upstream notice status: the installed releases `@npmcli/agent@5.0.2` (ISC) and `proxy-agent-negotiate@1.1.0` (MIT) omit standalone license text. THIRD_PARTY_NOTICES preserves their actual package declarations and author attribution, and identifies the missing texts. These dependencies are installed separately by npm; their code is not vendored into this tarball. The notice gaps remain open for upstream clarification.

For a reproducible report, include the profile, a minimal synthetic fixture, intent/patch, expected membership and public diagnostic codes. Review exports for project-specific information before sharing.

Unfinished HTTP disconnects cancel the request's queued or active calculation. Server close cancels all active/queued requests and waits for Worker exit and private-shadow cleanup. Cancelled calculations reject with AbortError/CANCELLED without advancing revision, report or history; completed responses remain committed.

Cleanup failures return `CLEANUP_FAILED` (CLI exit 3), an optional UUID `cleanupId`, and recovery guidance. They keep the last valid scene. Each cleanup attempt makes at most two removals with one 25 ms wait, after Worker exit; it does not renew the calculation deadline or start a Worker. The next calculation retries pending owned objects before creating another shadow. `retryCleanup(cleanupId)` and `retryPendingCleanup()` also perform bounded retries in the same process. Each ID resolves only to the in-memory creation record, and removal rechecks the real directory's device, inode and creation time. Unknown IDs, JSON and paths have no cleanup authority. Successful removal drops the record; failed records remain until recovered or the process exits. Concurrent already-running calculations can each leave a record, but subsequent shadow creation stops while any record remains blocked.

After CLI/process exit, release the blocking application and inspect the exact `packlens-shadow-<cleanupId>` folder in the operating system's temporary directory. Remove it manually only after confirming it is the tool-owned copy. Registration is process-local; a new process cannot accept an old report as deletion authority. Cancellation retains `AbortError`/`CANCELLED` and carries the optional safe `cleanupId` when cleanup also fails. Public JSON, HTML and CLI include this ID and guidance, with no absolute temporary directory or raw stack.

清理失败返回 `CLEANUP_FAILED`、UUID `cleanupId` 与恢复说明（CLI 退出码 3），保留旧有效场景。每次最多删除两次、间隔 25 ms，等待 Worker 退出后进行；下一次计算在新建副本前重试遗留对象。同进程可调用 `retryCleanup(cleanupId)` 或 `retryPendingCleanup()`；恢复核对创建记录及目录真实身份，成功后移除登记。CLI 退出后登记失效：释放占用程序，在系统临时目录检查精确名称 `packlens-shadow-<cleanupId>`，确认是本工具副本后手工移除。报告 ID 不授予其他进程删除权限。取消仍为 `AbortError`/`CANCELLED`，清理同时失败时附安全 ID。
